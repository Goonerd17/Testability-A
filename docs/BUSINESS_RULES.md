# 업무 규칙 (Business Rules) — Membership Billing Lab

- 버전: 1.0-draft · 작성일: 2026-10-12 · Phase 1
- 이 문서가 구현과 테스트의 **유일한 기준**이다. 테스트가 실패해도 이 문서를 임의로 바꾸지 않는다. 변경은 `DECISIONS.md`에 기록한 뒤 버전을 올린다.

## 0. 표기 규칙

| 표기 | 의미 |
|------|------|
| `BR-<영역>-NNN` | 규칙 ID. 한 번 부여한 ID는 재사용하지 않는다. 폐기 시 "폐기"로 표시하고 남겨 둔다. |
| **[요구-n]** | 사용자가 Phase 1에서 제시한 필수 업무 규칙 n번을 그대로 옮긴 것 |
| **[등급표]** | 사용자가 제시한 등급 정책 |
| **[결정]** | 요구가 명시하지 않은 부분을 Phase 1에서 확정한 것. 근거와 대안은 [OPEN_QUESTIONS.md](OPEN_QUESTIONS.md)에 있고, **사용자 승인 전까지 잠정 확정** 상태다. |

영역: `TIM` 시간·기간 · `AMT` 금액 · `TXN` 거래 · `RFD` 환불 · `PRF` 실적 · `GRD` 등급 · `FEE` 수수료 · `STL` 정산

## 1. 용어

| 용어 | 정의 |
|------|------|
| 정산월 `M` | 수수료를 계산하는 대상 월. `YYYY-MM` 형식 |
| 월 시작 `start(m)` | 월 `m`의 1일 00:00:00.000000000 (Asia/Seoul) |
| 월 구간 | `[start(m), start(m+1))` — 시작 포함, 끝 미포함 |
| 결제(Payment) | 사용금액을 증가시키는 거래 |
| 환불(Refund) | 특정 결제(원거래)에 연결되어 사용금액을 감소시키는 거래 |
| 귀속월 | 거래 금액이 반영되는 실적 월. 결제는 발생 시각의 월, 환불은 원거래의 귀속월 |
| 인식 시각 | 금액이 집계에 반영되기 시작하는 시각. 결제는 `occurredAt`, 환불은 `refundedAt` |
| 기준 시각 `asOf` | 집계 시 "이 시각 **이전**에 인식된 거래만 포함"하는 기준점 (`인식 시각 < asOf`) |
| 월 순사용금액 `NU(m, asOf)` | 귀속월이 `m`인 결제 합계 − 귀속월이 `m`이고 `refundedAt < asOf`인 환불 합계 |
| 등급 산정 기간 | 정산월 `M` 직전 12개 완료 월: `M-12` ~ `M-1` |
| 등급 실적 `GB(M)` | 등급 산정 기간의 순사용금액 합계 (기준 시각 `start(M)`) |
| 수수료 기준액 `FB(M)` | `NU(M, start(M+1))` — 정산월 자체의 순사용금액 |

## 2. 시간과 기간 (TIM)

| ID | 규칙 | 출처 |
|----|------|------|
| BR-TIM-001 | 모든 월 경계 판정은 **Asia/Seoul** 시간대 기준이다. 입력 시각은 오프셋을 포함한 ISO-8601이어야 하며, 오프셋이 다른 입력(예: UTC)은 Asia/Seoul로 환산해 판정한다. 오프셋이 없는 시각은 거부한다(`INVALID_REQUEST`). | [결정] |
| BR-TIM-002 | 월 구간은 `[start(m), start(m+1))`이다. 월말 23:59:59.999999999는 해당 월, 다음 달 1일 00:00:00은 다음 월이다. | [결정] |
| BR-TIM-003 | 거래 등록 시 거래 시각(`occurredAt`/`refundedAt`)은 **현재 시각 이하**이고 **현재 시각이 속한 월** 안에 있어야 한다. 이전 월로 소급하거나 미래 시각인 거래는 거부한다(`TRANSACTION_TIME_OUT_OF_OPEN_PERIOD`). | [결정] |
| BR-TIM-004 | "현재 시각"은 시스템이 주입받은 시계(Clock)로 결정한다. 같은 입력과 같은 현재 시각이면 결과가 같아야 한다. | [결정] |

> BR-TIM-003의 목적: 이미 시작된 월의 등급과 이미 끝난 월의 수수료 기준액이 **나중에 등록되는 거래로 바뀌지 않도록** 보장한다. 이 규칙 덕분에 BR-STL-003(결정적 결과)이 성립한다.

## 3. 금액 (AMT)

| ID | 규칙 | 출처 |
|----|------|------|
| BR-AMT-001 | 통화는 KRW, 최소 단위는 1원이다. 거래 금액은 정수이며 소수 금액은 거부한다(`INVALID_AMOUNT`). | [결정] |
| BR-AMT-002 | 거래 1건의 금액은 **1원 이상 1,000,000,000원 이하**다. 0, 음수, 상한 초과는 거부한다(`INVALID_AMOUNT`). 결제와 환불에 모두 적용한다. | [결정] |
| BR-AMT-003 | 금액의 합산과 수수료 중간 계산은 32비트 int 범위(2,147,483,647)를 넘어도 정확해야 한다. 64비트 정수 이상의 정밀도를 사용하고, 범위를 넘는 경우 값이 순환(wrap)되지 않고 오류(`AMOUNT_OVERFLOW`)가 나야 한다. | [요구-8] |

## 4. 거래 (TXN)

| ID | 규칙 | 출처 |
|----|------|------|
| BR-TXN-001 | 결제는 귀속월(발생 시각 기준 월)의 순사용금액을 결제 금액만큼 증가시킨다. | [요구-4] |
| BR-TXN-002 | 모든 거래(결제·환불)는 요청자가 부여한 `transactionId`를 가진다. `transactionId`는 결제·환불을 통틀어 **시스템 전역에서 유일**하다. | [결정] |
| BR-TXN-003 | 이미 등록된 `transactionId`로 **같은 내용**(회원, 거래 유형, 금액, 시각, 원거래 ID)을 다시 요청하면 새로 등록하지 않고 기존 거래를 그대로 반환한다(성공 응답). 집계에는 한 번만 반영된다. | [요구-7] + [결정] |
| BR-TXN-004 | 이미 등록된 `transactionId`로 **다른 내용**을 요청하면 거부한다(`DUPLICATE_TRANSACTION_CONFLICT`). 기존 거래는 변하지 않는다. | [결정] |
| BR-TXN-005 | 중복 여부는 `transactionId`로만 판단한다. ID가 다르면 회원·금액·시각이 같아도 서로 다른 정상 거래다. | [결정] |
| BR-TXN-006 | 존재하지 않는 회원의 거래는 거부한다(`MEMBER_NOT_FOUND`). | [결정] |
| BR-TXN-007 | 등록된 거래는 수정하거나 삭제할 수 없다. 결제를 보정하는 방법은 환불뿐이다. | [결정] |

## 5. 환불 (RFD)

| ID | 규칙 | 출처 |
|----|------|------|
| BR-RFD-001 | 환불은 원거래인 **결제**의 `transactionId`를 반드시 지정한다. 원거래가 없으면 `PAYMENT_NOT_FOUND`, 다른 회원의 결제면 `PAYMENT_NOT_FOUND`(타 회원 거래의 존재를 노출하지 않음)로 거부한다. | [요구-5] + [결정] |
| BR-RFD-002 | 환불의 귀속월은 **원거래의 귀속월**이다. 환불이 처리된 월이 아니다. | [요구-5] |
| BR-RFD-003 | 하나의 결제에 대해 부분 환불과 여러 번의 환불을 허용한다. | [결정] |
| BR-RFD-004 | 한 결제의 누적 환불액은 원결제 금액을 초과할 수 없다. 이번 환불을 더하면 초과하는 요청은 **전체를 거부**한다(`REFUND_EXCEEDS_REMAINING`). 남은 금액만큼만 부분 수용하지 않는다. | [요구-6] + [결정] |
| BR-RFD-005 | 환불 대상은 결제만 가능하다. 환불을 원거래로 지정하면 거부한다(`INVALID_REFUND_TARGET`). | [결정] |
| BR-RFD-006 | `refundedAt`은 원거래의 `occurredAt`보다 이전일 수 없다(같은 시각은 허용). 위반 시 `INVALID_REFUND_TIME`. | [결정] |
| BR-RFD-007 | 환불 기한은 없다. 등급 산정 기간을 벗어난 오래된 결제도 환불할 수 있다(이 경우 어떤 미래 등급에도 영향이 없을 수 있다). | [결정] |
| BR-RFD-008 | 환불은 `refundedAt` 시각부터 집계에 인식된다. 기준 시각 `asOf` 이후에 인식된 환불은 그 `asOf`로 확정한 등급·수수료에 영향을 주지 않는다. | [결정] |
| BR-RFD-009 | **환불이 과거 등급에 미치는 영향**: 이미 확정된 등급(이미 시작된 정산월의 등급)은 바꾸지 않는다. 환불은 그 귀속월이 등급 산정 기간에 포함되는 **이후 정산월의 등급에만** 반영된다. | [결정] |
| BR-RFD-010 | 환불은 다른 월의 순사용금액을 상계하지 않는다. 귀속월의 순사용금액만 감소시킨다. | [요구-5] |

## 6. 실적 (PRF)

| ID | 규칙 | 출처 |
|----|------|------|
| BR-PRF-001 | 월 순사용금액 `NU(m, asOf)` = Σ(귀속월 `m`인 결제 금액, `occurredAt < asOf`) − Σ(귀속월 `m`인 환불 금액, `refundedAt < asOf`) | [요구-4,5] + [결정] |
| BR-PRF-002 | 정산월 `M`의 등급 실적 `GB(M)` = Σ `NU(m, start(M))`, `m ∈ {M-12, …, M-1}` (직전 12개 완료 월) | [요구-2] |
| BR-PRF-003 | 정산월 `M` 자체(당월)의 거래는 `GB(M)`에 포함하지 않는다. `M-13` 이전 월도 포함하지 않는다. | [요구-3] |
| BR-PRF-004 | 거래가 없는 월의 순사용금액은 0이다. 가입 기간이 12개월 미만이거나 이력이 없는 회원도 같은 공식으로 계산한다. | [결정] |
| BR-PRF-005 | **음수 순사용금액 정책**: BR-RFD-002, BR-RFD-004, BR-RFD-010에 의해 모든 `NU(m, asOf)`는 0 이상이어야 한다(불변식). 계산 결과가 음수이면 데이터 무결성 위반으로 보고 오류(`NEGATIVE_NET_USAGE`)를 낸다. **0으로 보정하거나 다른 달과 상계하지 않는다.** 이 경우 정산 결과를 저장하지 않는다. | [결정] |

## 7. 등급 (GRD)

| ID | 규칙 | 출처 |
|----|------|------|
| BR-GRD-001 | 등급과 구간 (`GB` 기준, 하한 **이상** 포함 · 상한 **미만**) | [등급표] |

| 등급 | 하한 (이상) | 상한 (미만) | 수수료율 | 베이시스 포인트(bp) |
|------|------------|------------|----------|------|
| BASIC | 0 | 1,000,000 | 3.0% | 300 |
| SILVER | 1,000,000 | 5,000,000 | 2.0% | 200 |
| GOLD | 5,000,000 | 10,000,000 | 1.0% | 100 |
| VIP | 10,000,000 | 없음 | 0.5% | 50 |

| ID | 규칙 | 출처 |
|----|------|------|
| BR-GRD-002 | 정산월 `M`의 등급은 `start(M)` 시점에 확정된다. 즉 기준 시각 `start(M)`으로 계산한 `GB(M)`으로 결정한다. 등급 계산을 실제로 언제 수행하든 결과는 같다. | [요구-1] + [결정] |
| BR-GRD-003 | 확정된 등급은 이후 등록되는 어떤 거래(환불 포함)로도 바뀌지 않는다. | [요구-1] + [결정] |
| BR-GRD-004 | 거래 이력이 없는 회원은 `GB = 0`이므로 BASIC이다. | [결정] |

## 8. 수수료 (FEE)

| ID | 규칙 | 출처 |
|----|------|------|
| BR-FEE-001 | 수수료 기준액 `FB(M)` = `NU(M, start(M+1))`. 정산월이 끝나는 시점까지 인식된 당월 귀속 거래만 포함한다. | [요구-9] + [결정] |
| BR-FEE-002 | 수수료 = `FB(M) × bp(등급(M)) ÷ 10,000` 를 **원 단위로 반올림(HALF_UP, 0.5원 이상 올림)** 한 값이다. 수수료율은 실수(float/double)가 아니라 bp 정수 또는 정확한 십진수로 다룬다. | [요구-9,10] + [결정] |
| BR-FEE-003 | 반올림은 **월 수수료 합계에 한 번만** 적용한다. 거래별로 반올림한 뒤 합산하지 않는다. | [결정] |
| BR-FEE-004 | `FB(M) = 0`이면 수수료는 0원이다. 최저·최고 수수료는 없다. | [결정] |
| BR-FEE-005 | 수수료는 0 이상이다. 음수 수수료(환급)는 발생하지 않는다(BR-PRF-005). | [결정] |

반올림 예시 (BR-FEE-002): `900 × 50 ÷ 10,000 = 4.5 → 5원`, `899 × 50 ÷ 10,000 = 4.495 → 4원`, `16 × 300 ÷ 10,000 = 0.48 → 0원`.

## 9. 정산 (STL)

| ID | 규칙 | 출처 |
|----|------|------|
| BR-STL-001 | 정산 단위는 (회원, 정산월)이다. 정산은 요청 시 계산되어 **즉시 확정(CONFIRMED)** 된다. 초안(DRAFT) 상태는 없다. | [결정] |
| BR-STL-002 | 정산월이 끝난 뒤(`현재 시각 ≥ start(M+1)`)에만 정산할 수 있다. 진행 중인 월이나 미래 월은 거부한다(`SETTLEMENT_PERIOD_NOT_CLOSED`). | [결정] |
| BR-STL-003 | 정산 결과는 `GB(M)`(기준 시각 `start(M)`)과 `FB(M)`(기준 시각 `start(M+1)`)로만 결정되며, **정산 요청 시각과 무관**하다. | [결정] |
| BR-STL-004 | **멱등성**: 같은 (회원, 정산월)에 대한 재요청은 새로 계산하지 않고 최초 확정 결과(정산 ID, 등급, 금액, 확정 시각 포함)를 그대로 반환한다. | [요구-11] |
| BR-STL-005 | 같은 (회원, 정산월)에 대한 요청이 동시에 들어와도 확정 정산은 정확히 1건만 생성되며, 모든 요청이 같은 결과를 받는다. | [요구-11] |
| BR-STL-006 | **확정 정산 불변 · 재정산 정책**: 확정된 정산은 수정·삭제·재계산하지 않으며, 이를 위한 기능을 제공하지 않는다. "재정산 요청"은 BR-STL-004의 재요청으로 처리되어 최초 결과를 반환한다. | [요구-12] + [결정] |
| BR-STL-007 | **정산 후 발생한 환불**: 이미 끝난 정산월에 귀속되는 환불(정산월 종료 후 처리된 환불)은 그 월의 수수료에 반영하지 않으며, 수수료 환급·차감·이월 조정도 하지 않는다. 해당 환불은 BR-RFD-009에 따라 이후 등급에만 영향을 준다. | [결정] |
| BR-STL-008 | 거래가 없는 월도 정산할 수 있다. 결과는 해당 등급, 수수료 기준액 0, 수수료 0원이다. | [결정] |
| BR-STL-009 | 각 정산월은 독립적으로 계산한다. 이전 월의 정산 존재 여부와 무관하며, 순서와 상관없이 정산할 수 있다. | [결정] |
| BR-STL-010 | 정산월 형식은 `YYYY-MM`이다. 잘못된 형식이나 존재하지 않는 월(예: `2026-13`)은 거부한다(`INVALID_SETTLEMENT_MONTH`). | [결정] |
| BR-STL-011 | 확정 정산에는 최소한 다음 항목을 기록한다: 정산 ID, 회원 ID, 정산월, 등급, 등급 실적(`GB`), 산정 기간(시작월·종료월), 수수료 기준액(`FB`), 적용 bp, 수수료, 확정 시각. | [결정] |
| BR-STL-012 | 존재하지 않는 회원의 정산 요청은 거부한다(`MEMBER_NOT_FOUND`). | [결정] |
