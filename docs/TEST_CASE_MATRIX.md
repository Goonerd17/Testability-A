# 테스트 케이스 매트릭스 — Membership Billing Lab

- 버전: 1.0-draft · 작성일: 2026-10-12 · Phase 1
- 기준 문서: [BUSINESS_RULES.md](BUSINESS_RULES.md) v1.0-draft
- 모든 기대값은 업무 규칙에서 **사람이 직접 계산한 값**이다. 구현 결과를 보고 기대값을 고치지 않는다(작업 원칙 5).
- 이 문서는 시나리오 정의이며 테스트 코드는 아직 없다.

## 0. 공통 전제

| 항목 | 값 |
|------|----|
| 시간대 | 모든 시각은 별도 표기가 없으면 `+09:00` (Asia/Seoul) |
| 회원 | `M1`, `M2` (사전 존재). `M9`는 존재하지 않는 회원 |
| 기본 정산월 | `2026-07` → 등급 산정 기간 `2025-07` ~ `2026-06` |
| 기본 정산 요청 시각 | `2026-08-10T10:00:00+09:00` |
| 거래 등록 시각 | 각 거래는 BR-TIM-003을 만족하도록, 거래 시각이 속한 월의 Clock으로 등록한다. (Fake 저장소에 직접 적재하는 것은 TC-NEG-03/04처럼 명시한 경우만) |
| 시각 약식 | `07-15`는 `2026-07-15T12:00:00+09:00`. 연도가 다르면 `2025-09-15`처럼 쓴다 |
| 등급 준비 데이터 | **SILVER창**: `2026-01-15` 결제 1,000,000 / **GOLD창**: `2026-01-15` 결제 5,000,000 / **VIP창**: `2026-01-15` 결제 10,000,000 / **빈창**: 산정 기간에 거래 없음 |
| 결과 표기 | `등급 / GB / FB / 수수료`. GB=등급 실적, FB=수수료 기준액 |
