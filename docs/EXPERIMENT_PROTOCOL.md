# 실험 프로토콜

이 문서는 AI 생성 코드의 테스터빌리티 실험을 **재현 가능하고 비교 가능하게** 수행하기 위한 절차와 보존 규칙을 정의한다.

## 1. 실험 단위와 식별자

- 실험 하나 = "하나의 프롬프트(또는 프롬프트 묶음)로 AI가 코드/테스트를 생성하고, 이를 측정·분석하는 한 사이클".
- 식별자: `EXP-NNN-<짧은-영문-슬러그>` (예: `EXP-001-baseline-settlement`)
- 번호는 1부터 순차 증가하며 재사용하지 않는다. 폐기한 실험도 번호와 폐기 사유를 남긴다.

## 2. 보존 방식 (3중 보존)

AI 최초 산출물은 이후 수정과 비교해야 하므로 아래 세 가지 방법으로 동시에 보존한다.

### 2.1 실험 디렉터리 스냅샷 — `experiments/EXP-NNN-<slug>/`

```
experiments/EXP-NNN-<slug>/
├── README.md        # 실험 메타데이터: 목적, 가설, 일시, 모델, 도구, 담당자, 관련 커밋/태그
├── prompt.md        # AI에게 준 프롬프트 원문 (한 글자도 수정하지 않음). 여러 턴이면 순서대로 모두
├── response.md      # AI 응답 원문 중 코드 외 설명 부분 (필요 시)
├── ai-original/     # AI가 최초 생성한 파일의 원본 복사본 (src 경로 구조를 유지)
├── reports/         # 실제 측정 도구의 원본 리포트 (JaCoCo XML/CSV, PIT, PMD 등)
└── result.md        # 측정 결과 요약, 관찰, 실패 원인, 수정 이력
```

- 템플릿: [`experiments/_TEMPLATE/`](../experiments/_TEMPLATE/)
- **`ai-original/`과 `prompt.md`는 생성 후 절대 수정하지 않는다.** 오타가 있어도 그대로 둔다.
- `ai-original/`의 파일은 컴파일 대상이 아니다(`src/` 밖에 있으므로 Gradle 빌드에 포함되지 않음).

### 2.2 Git 커밋과 태그

| 시점 | 커밋 메시지 접두어 | 태그 |
|------|-------------------|------|
| 프롬프트 기록 | `exp(NNN): prompt` | — |
| AI 최초 산출물을 `src/`에 그대로 반영 | `exp(NNN): ai-original` | `exp-NNN-ai-original` |
| 최초 측정 완료 | `exp(NNN): measure baseline` | `exp-NNN-baseline` |
| 사람/AI의 개선 수정 (회차별) | `exp(NNN): fix-K <요약>` | `exp-NNN-fix-K` |

- `ai-original` 커밋에는 **AI 산출물 외의 변경을 섞지 않는다.** (컴파일이 안 되더라도 그대로 커밋하고, 실패 사실을 기록)
- 비교는 `git diff exp-NNN-ai-original exp-NNN-fix-K` 로 수행한다.
- 태그는 annotated tag(`git tag -a`)로 만들고 메시지에 실험 ID와 모델명을 적는다.

### 2.3 실험 로그 — `docs/AI_EXPERIMENT_LOG.md`

실행한 명령어, 결과, 실패 원인, 수정 이력을 시간 순으로 기록한다. 로그는 추가만 하고(append-only) 과거 항목을 고치지 않는다. 정정이 필요하면 새 항목에 "정정"으로 남긴다.

## 3. 실험 절차

1. **준비**: 실험 ID 발급, `experiments/_TEMPLATE`을 복사해 디렉터리 생성, README.md에 목적·가설 작성.
2. **프롬프트 기록**: 프롬프트 원문을 `prompt.md`에 저장 후 커밋.
3. **생성**: AI에게 프롬프트 제공. 사용한 모델명/버전, 도구(예: Claude Code), 일시를 기록.
4. **원본 보존**: 생성된 파일을 `ai-original/`에 복사하고, 동일 내용을 `src/`에 반영해 `ai-original` 커밋 + 태그.
5. **최초 측정**: 정해진 측정 명령을 실행(§4). 원본 리포트를 `reports/baseline/`에 복사, 수치는 `TEST_RESULTS.md`에 기록.
6. **분석**: 테스트하기 어려운 지점(숨은 의존성, 시간/난수, static, 거대 메서드 등)을 `result.md`에 기록.
7. **개선(선택)**: 수정은 회차별로 커밋하고, 매 회차 측정을 다시 수행.
8. **정리**: `result.md`에 baseline 대비 변화와 결론을 작성.

## 4. 측정 규칙

- 수치는 **도구가 출력한 원본 리포트**에서만 옮겨 적는다. 추정치, 기억에 의존한 수치, 반올림 조작 금지.
- 각 수치 옆에 측정 명령어, 측정 일시, 커밋 해시를 함께 적는다.
- 측정 도구와 버전은 실험 간 동일하게 유지한다. 바꿔야 하면 `DECISIONS.md`에 기록하고 이전 실험과 직접 비교하지 않는다.
- 측정이 실패하면 "측정 실패"와 원인을 기록한다. 빈칸을 추정값으로 채우지 않는다.

## 5. 수정 규칙

- 테스트 실패를 이유로 업무 명세를 변경하지 않는다. 명세가 틀렸다고 판단되면 질문으로 남기고 확인받는다.
- **기능 코드와 테스트 코드를 한 커밋에서 동시에 수정하지 않는다.** 한쪽을 수정한 뒤 다른 쪽의 결과를 관찰한다.
- 테스트 대역은 가능하면 Fake 구현을 우선 사용한다. Mockito를 사용한 경우 사유를 `result.md`에 적는다.

## 6. 데이터 규칙

- 과거 회사의 비공개 소스, 고객 데이터, 실제 개인정보를 사용하지 않는다.
- 테스트 데이터는 직접 만든 합성 데이터만 사용한다.
